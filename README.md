# 麦有数

> 点前算清，点后有数。

基于麦当劳 MCP 的点餐决策作品，包含**实时交互网页**和**可安装 Skill**。选择门店，按预算、能量和餐品需求比较候选，再保持主食只换一项，查看重新核价后的差别。独立参赛作品，非麦当劳官方产品。

**目标用户**：在麦当劳柜台或自助点餐机前，需要快速判断“这一餐多少钱、多少能量、换哪一样更合适”的点餐人；也适合关注能量摄入、需要控制预算或只想点得更明白的普通顾客。

## 当前可用功能

- 城市＋地标查询门店列表，点击选择；参考距离不冒充手机定位。
- 查询该门店即时到店自取菜单、套餐组成及可替换选项。
- 设置1—4人、总预算、每人能量上限、价格/能量/蛋白质优先级，以及饮料、薯条与餐品名称排除关键词。
- 对有限候选逐一真实核价，再比较满足条件的方案；无满足项时明确展示差额。
- 选择一套作为基线，仅替换一个配菜或饮料；基线与替换分别重新核价。
- 官方营养 TOON 按餐品名称与规格匹配；缺失显示未知，明确的0值保留。
- 下载不含账号和券码的本轮比较 JSON。
- 查询门店适用券状态；**网页尚不自动套券**，不能把查到券当作已经使用。优惠查询失败和无适用券分别显示。

所有功能仅查询与试算。服务端只允许六个工具，不含下单、付款、领券或购卡。

## 运行网页

需要 Python 3.10 或更新版本，全部使用标准库，无需安装依赖。

1. 在支持麦当劳 MCP 的客户端中配置好官方服务，或在运行环境设置 `MCD_MCP_TOKEN`。
2. 在项目根目录执行：

```bash
python server.py
```

3. 打开 http://127.0.0.1:8765 。页面实际检查连接后，默认搜索“上海·张江高科”；点击门店，再点击“选好了，看看菜单”。
4. 选择套餐、设置目标，先“试算当前搭配”或“核价并比较候选方案”；在结果页选择基线，点击“比较一个配菜或饮料的替换”。

默认读取当前操作系统用户的 `~/.workbuddy/mcp.json`，其次读取项目 `.workbuddy/mcp.json`；从中只识别官方 `https://mcp.mcd.cn` 的认证配置。环境变量 `MCD_MCP_TOKEN` 优先。凭证仅留在本机服务内存，不返回网页、不写入仓库。

`mcp-config.example.json` 仅为脱敏结构示例；`${MCD_MCP_TOKEN}` 表达环境变量占位，不保证每个客户端自动展开。按所用客户端的官方方式设置实际值。不要将真实凭证提交到公开仓库。

**直接双击 HTML 无法执行实时查询**，页面会提示运行本机服务。服务仅绑定127.0.0.1，不对局域网开放。复制项目到其他电脑后，需要用该使用者自己的授权配置运行。未发布公共在线服务，不共享作者账号。

服务每次运行为本机 API 生成随机访问令牌，并只随所服务页面注入；页面请求自动携带，可阻止本机其他不带来源的脚本直接调用接口。服务重启后令牌改变，已打开的旧页面需刷新。可用环境变量 `MAIYOUSHU_API_TOKEN` 指定固定令牌（16—256 位，限字母数字及 `._~+-/`）。该令牌与官方 MCP 凭证相互独立，不写入仓库、分发包或日志。

## 使用 Skill

将 `skills/maiyoushu` 文件夹放入宿主的技能目录（WorkBuddy 用户级路径为 `~/.workbuddy/skills/maiyoushu`），保留 `SKILL.md` 与 `references` 目录。已有麦当劳 MCP 配置后，可以自然语言提出：

> 用麦有数，在上海张江高科附近选一家到店自取门店。一人预算35元，850千卡以内。先列门店让我选，只查询和试算。

> 主食和中薯不变，只把中杯可乐换成无糖，重新核算价格与能量差。

Skill 直接使用宿主已授权的 MCP，与网页共享决策规则，运行时不依赖本机网页服务。安装包在发行作品包的 `outputs/maiyoushu.zip` 中。未在全新宿主验证自动安装流程，目录安装后以宿主重新发现技能为准。

## 真实验证

2026-10-25，上海张江中兴智慧园餐厅（1450359），即时到店自取：

| 板烧三件套搭配 | 独立核价 | 标准份能量 |
| --- | ---: | ---: |
| 板烧＋中薯＋中杯可乐 | ¥34.50 | 827千卡 |
| 仅换无糖中杯 | ¥34.50 | 680千卡 |
| 仅把中薯换小杯玉米，保留可乐 | ¥34.00 | 591千卡 |
| 玉米＋无糖的双项替换 | ¥34.00 | 444千卡 |

最后一行改变两项，不称为“只改一处”。价格是当次查询证据，不是今后报价。门店适用券当次成功返回空数组，不能推断为整个账号没有券。

真实 Edge 浏览器完成22项检查，覆盖搜索、选店、选餐、核价、15个候选、单项比较、低预算提示及390px手机布局。故障注入另覆盖价格、营养、优惠查询失败。自动测试：后端35项、计算逻辑6项、审计回归8项，共49项全部通过。浏览器验证结果见 `outputs/browser-real-results.json` 与 `outputs/browser-real-comparison.json`；复测说明见 `docs/VALIDATION.md`，安全与逻辑审计见 `outputs/AUDIT_REPORT.md`。

针对审计中三项未覆盖限制的复测（服务端15项＋浏览器10项）已通过：无令牌请求被 403 拒绝；六个工具的真实官方 schema 均被失败关闭策略接受，合法调用不被误拒；门店、菜单、营养、优惠券与核价真实调用全部成功，板烧三件套仍为 ¥34.50、827 千卡。证据在 `outputs/revalidation-real-link.json` 与 `outputs/revalidation-browser.json`。

## 能力范围

- 网页目前支持即时到店自取，相同份数按人数复制；不支持逐人不同配餐、预约、外送、得来速或下单。
- 候选不是全菜单穷举，不宣称全局最优；复杂多选套餐会被跳过，部分单品没有完整搭配。
- 原料批次、标准配方与实物份量存在差异。能量是标准份参考，不能作为医疗依据。名称过滤不保证没有某种配料或过敏原。
- 部分新餐品没有营养数据；未知不会计为0，也不会被判断为满足能量上限。
- 存在购卡条件或无法确认优惠资格的商品排除自动比较，未实现自动领取优惠券。
