# 麦当劳 MCP 赛事作品调研与差异化结论

> 调研时间：2026-10-25（北京时间）
> 样本范围：官方仓库 `M-China/mcd-developer-innovation-challenge` 的公开 Issues，重点分析 API 第 1 页返回的 100 条开放 Issue（仓库页面显示全量 Issue 约 1207 条）。因此以下统计用于方向判断，不代表全部参赛作品的最终完整排名。

## 一、结论先行

当前最拥挤的方向是：

1. **通用点餐助手 / 套餐推荐**：一句话点餐、三套方案、套餐自选、确认式下单；
2. **省钱 / 优惠券 / 预算优化**：查券、凑单、满减、券后价、积分/卡；
3. **营养 / 热量 / 减脂配餐**：热量、蛋白、低脂、低钠和减脂方案；
4. **多人聚餐 / 拼单 / AA 分账**：多人约束、拆单、满减、分摊；
5. **人格化与娱乐化**：人格报告、小游戏、盲测、生成分享卡。

单独做“预算 + 能量 + 优惠券的最优组合”已经很容易与多个作品重叠，包括：

- `mcd-calorie-coach`：热量预算、多套菜单、周计划；
- 麦当劳营养膳食专家：基于营养矩阵的配餐闭环；
- 麦门超级管家：省钱控卡、券、营养、积分提醒和分享；
- 麦门省钱军师：巡券、凑单、活动日历、积分和营养；
- 麦麦信徒究极帮手：一句话、三个已核价方案；
- 麦当劳省钱点餐助手：人数、预算、忌口、同款上限求最省；
- 麦记营养师：热量预算内最大化蛋白或最低热量达标；
- 麦门全能点餐助手：聚餐、省钱、热量、套餐、活动五大场景。

## 三、差异化机会

### 推荐方向：麦有数的反事实复盘

把作品从“帮你点一单”升级为：

> **点之前预测：这单最可能哪里后悔？点之后复盘：下一次怎样改一处就更合适？**

它不是再做一层推荐，而是做一个“点餐决策的可逆性与复盘系统”。核心概念：

- **决策账本**：记录用户当时的预算、能量上限、口味、渠道、门店、优惠与最终方案；
- **后悔成本**：把“贵了多少、超了多少能量、缺了什么、剩了多少、优惠是否真正生效”拆开；
- **反事实重算**：只改一个变量，重新用 MCP 核价，例如“同样的餐改成到店自取”“不为了凑券加购”“薯条换玉米”“换另一个门店”；
- **下一次可执行规则**：自动沉淀为“下次点餐协议”，例如“不为省 ¥6 多花 ¥18”“外送比自取贵 ¥14 时，只有时间价值超过 ¥14 才选外送”；
- **可解释复盘卡**：不是评价用户对错，而是回答“当时为什么这样选、现在能改什么、下次默认怎么做”。

### 为什么这个方向更有辨识度

- 省钱类作品很多，但多数关注“现在怎样最省”；麦有数 关注“上次为什么不划算、下次如何避免重复踩坑”；
- 营养类作品很多，但多数关注“现在怎样低热量”；麦有数 关注“实际吃完的体验与预期的偏差”；
- 记忆类作品已有 `MaiMate`，但它偏向口味记忆和推荐；麦有数 偏向可验证的决策结果记忆和反事实比较；
- 质检/工程类已有作品，但 麦有数 是用户可理解的“订单复盘”，兼具实用性和故事性；
- MCP 的实时能力在这里不是装饰：复盘必须重新查询门店菜单、营养、券和 `calculate-price`，才能证明“改一处”带来的真实变化。

## 四、建议的最小可行版本

首版不要试图做订单全生命周期。只做一个强闭环：

1. 用户输入/粘贴一个想点的方案，或先用麦有数生成方案；
2. 选择两三个真实约束：预算、能量、渠道、优惠；
3. 点击“找出这单最可能后悔的地方”；
4. 系统用 MCP 做三种反事实重算：
   - 不用券 / 换可用券；
   - 自取 / 外送 / 得来速；
   - 保持主食，替换一个高能量或不划算的配菜；
5. 输出“后悔雷达”：价格、能量、优惠、满足感、复杂度；
6. 给一个“一键改一处”的下次规则。

## 五、评分与安全建议

- 价格：只认 `calculate-price`，金额统一用分做整数运算；
- 优惠：只认当前门店/订单类型下可用券，不能把卡包中的券直接当成可用券；
- 营养：缺失时标记“未知”，不擅自填 0；
- 用户确认：默认只读，不自动领券、不自动下单；
- 复盘结论：不使用“智商税”等羞辱性话术，不给医疗或营养诊断；
- 展示：同时保留“当时最优”和“如果重来一次”，避免把事后结果伪装成当时可知信息。

## 六、与当前项目的关系

作品正式名称统一为“麦有数”，宣传语为“点前算清，点后有数”。方案推荐与复盘使用功能名称，组成以下流程（当前页面为演示数据原型，实时核价待接入）：

```text
点餐推荐：现在怎么点更合适？
        ↓
反事实复盘：如果已经点过 / 有一套草稿，哪里最可能后悔？
        ↓
反事实重算：只改一个变量，真实价格与能量会怎样？
        ↓
下次点餐协议：沉淀成下一次可执行的个人规则
```

这样作品同时具备：

- 当前决策：有用；
- 事后复盘：有记忆点；
- MCP 真实调用：有技术证据；
- 用户可复用：有长期价值；
- 与已有通用省钱/营养/点餐助手：有明确区分。
